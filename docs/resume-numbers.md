## Numbers you may NOT use

- **Any hard-set ranking.** N = 40, AI-drafted and AI-verified, read by the engine's author on Day 1. Quote a hard-set number only as a caveat, with N, never to say one system is better.
- **Any claim that the agent beats the rules.** On the test split the agent's auto-correct interval overlaps the rules-only interval and its false-repair count is the same; do not claim an accuracy gain.
- **Any claim of compliance or certification** with CBPR+ or ISO 20022. Say: implements a documented subset of CBPR+ address rules.
- **Dev or calibration numbers**, the engine was tuned on them (they are optimistic).
- **Injection resistance as evidence of safety.** The slice is 15 AI-written cases and every system passed, so it cannot tell them apart.
- **Any real-bank, real-customer or production claim.** All data is synthetic.
- **A cutover date** for structured addresses. Swift's timing is not fixed (see the README).

## Likely interview questions

**Is the agent better than the rules?** Not on accuracy. On the test split: auto-correct 89.0% (890/1000) against 88.4% (884/1000), and the same false-repair count (0.2% (2/892) against 0.2% (2/886)). What it adds is routing: the 10.8% (108/1000) records it sends to review instead of publishing.

**Why not just use the LLM?** On the same synthetic test split it auto-corrects more (96.2% (962/1000)) but falsely repairs 3.4% (34/996) of what it accepts, with no verifier, against 0.2% (2/892) for the agent. In a payments setting a wrong accepted address is the expensive error.

**Is the cost advantage real?** On the test split, yes ($0.0066 against $0.2629 per 1,000). On the hard set no: $0.7580 against $0.2579, because most hard records reach the model.

**How reliable are these numbers?** They are on synthetic data that shares a generator and GeoNames with the rules, so they are optimistic. The hard set is small, AI-drafted and AI-verified. Each system was run once; temperature cannot be set on this model.

**Did the verifier catch every bad repair?** No. 2 false repairs got through, the same two failure patterns as the rules-only run; each has real text in the wrong field, which the grounding check cannot see.

**What is the weakest country?** India: rules-only auto-correct was 40.0% (50/125) on the test split.

**Is it CBPR+ compliant?** No. It implements a documented subset of CBPR+ address rules; the validator checks only a small subset, and the real hybrid-address limit is unconfirmed.
